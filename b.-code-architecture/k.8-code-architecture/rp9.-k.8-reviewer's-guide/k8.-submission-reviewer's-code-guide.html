K8. SUBMISSION REVIEWER'S CODE GUIDE

DOCUMENT OVERVIEW

This guide explains three independent computational validators:

  • K8. A: comparison of two separately implemented operator paths.
  • K8. B: exact relational invariance through repeated binary-scale expansion.
  • K8. C: finite Base-10 projection of established rational states followed by exact rational reconstruction.

It identifies their executed scopes, evidence, recorded results and validation boundaries.

1. EXECUTABLE IDENTITIES

Python code ID Executable Official code title
K8. A K8. A.py K8. P.B.F. ↔ BINARY PULSE OPERATOR IDENTITY VALIDATOR
K8. B K8. B.py K8. P.B.F. BINARY-SCALE INVARIANCE VALIDATOR
K8. C K8. C.py K8. P.B.F. BINARY STRUCTURE → BASE 10 PROJECTION LOCK VALIDATOR

The programs are self-contained. They require no master program and do not consume one another's output files.

Their assigned controls concern operator identity, binary-scale invariance and representation preservation. They do not rerun or extend the K.7 positional genealogy.

2. K8. A — OPERATOR IDENTITY

Executed function

K8. A compares two separately implemented paths identified as P.B.F. and Binary Pulse.

It tests whether they produce the same complete executed state throughout the tested domain by comparing:

  • complete candidate fields;
  • complete projected-hit structures;
  • state classification at every tested position;
  • complete closure sequences;
  • observation, closure and reproduced-position counts;
  • the location of any first deviation.

Equal totals alone do not establish executed operator identity.

Scope and recorded result

The recorded execution uses the limit:

1000000.

Prime-reference information is neither used nor reported by K8. A.

Result field Recorded result
Every identity condition PASS
Operator identity PASS
First deviation NONE

3. K8. B — BINARY-SCALE INVARIANCE

Executed function

K8. B.py, version 2.1.0, tests these rational families:

12,34,14,

together with complementary closure:

34+14=1.

Execution begins at level zero. Numerators and denominators are doubled at each following level.

Relation Executed scale sequence
Half 12 →24 →48 →816 →…
Three-quarter 34 →68 →1216 →2432 →…
One-quarter 14 →28 →416 →832 →…
Complete relation 34 +14 =1 at every level.

At each level, the program verifies:

  • exact quotient equality;
  • the three-quarter-to-one-quarter ratio;
  • a shared denominator;
  • binary denominator growth;
  • complete complementary closure.

Between adjacent levels, it verifies that the numerators and denominators of all three families are multiplied by two.

The written fractions expand while their rational values remain unchanged.

Exactness and recorded result

All status-bearing calculations use fractions.Fraction. Floating-point arithmetic and numerical tolerance do not determine the result.

Result field Recorded result
Binary-scale levels 8 of 8 PASS
Adjacent transitions 7 of 7 PASS
Global status PASS

4. K8. C — BASE-10 PROJECTION AND RECONSTRUCTION

Executed function

K8. C tests whether established rational states can be represented as finite Base-10 strings and reconstructed as their original exact fractions without value displacement or information loss.

The operation is:

Established rational state⟶Exact Fraction⟶Finite Base-10 string⟶Exact rational reconstruction.

Base 10 is a downstream representation layer. It does not generate or modify the source relations.

Operations performed

K8. C.py constructs exact Fraction representations of the established rational values at each binary-scale level before projection.

Each exact fractional state is then encoded as a Base-10 string. The string is decoded into an exact Fraction and compared with the source value.

Rational source state Base-10 representation Exact reconstruction
12 0.5 12
34 0.75 34
14 0.25 14
18 0.125 18
1 1 1

The validator checks that:

  • every exact fraction reconstructs without loss;
  • equivalent binary-scale expressions produce the same Base-10 representation;
  • 34 +14 =1 remains exact;
  • Base-10 encoding introduces no new rational state.

Exactness and recorded result

The validator uses reduced exact rational values whose denominators permit terminating Base-10 expansions.

Floating-point arithmetic and numerical tolerance do not determine the result.

Result field Recorded result
Projection levels 8 of 8 PASS
Cross-level representation identity PASS
BASE-10 PROJECTION LOCK PASS

7. TECHNICAL INSPECTION

The three inspection questions are:

  1. Operator: Do the separately implemented paths produce the same complete tested state, including fields, hits, classifications, closure sequences and counts?
  2. Scale: Do the defined rational values remain exact while their fractional representations expand through binary scaling?
  3. Representation: Do the defined rational states retain exact identity through finite Base-10 encoding and rational reconstruction?

Inspect the executable implementations and their recorded evidence for the stated scopes and conditions. Counts alone are insufficient for the operator-identity control.

8. VALIDATION BOUNDARY

Validator Executed scope
K8. A Operator identity between two separately implemented paths through the finite tested limit of 1 000 000.
K8. B Exact rational invariance across eight binary-scale levels and seven adjacent transitions.
K8. C Exact finite Base-10 projection and rational reconstruction for the defined source states across eight projection levels.

The validators operate on established relations. They do not independently derive their conceptual origin or introduce P.B.F. as an external formula applied to another program's output.

Their recorded results do not extend the K.7 genealogy or establish unexecuted domains.

K8. C tests representation preservation for the defined rational states; it does not derive the Base-10 number system.

The K.8 results are limited to the executed controls. They do not independently determine the Riemann Hypothesis or perform the formal final review.
