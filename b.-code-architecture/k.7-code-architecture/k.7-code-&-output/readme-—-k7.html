README — K7

DOCUMENT OVERVIEW

This package provides a segmented P.B.F. positional genealogy generator and an independent positional comparison.

It constructs the locked observation field, applies internally generated genealogical references through sequential endpoint continuation, and records the surviving closure positions.

Each completed internal segment is compared byte for byte with a separately constructed conventional prime-reference segment.

This README explains the local mechanism, execution parameters, recovery procedure, evidence files and recorded results.

2. LOCAL FUNCTION AND DEFINITIONS

The implemented sequence is:

Locked observation field → sequential addition → genealogical coincidence → reproduced position or new closure.

The program processes consecutive segments from position 0 through the requested maximum limit, inclusive. Smaller requested limits are cumulative milestones within the same continuous execution.

The default maximum is:

𝑁=100000000000.

No output from another K.6, K.7 or K.8 script is required.

The observation streams are:

6𝑘−1,6𝑘+1,𝑘≥1.

Their construction advances sequential endpoints by 6.

3. INTERNAL GENERATION

generate_internal_references() constructs the locked observation field through the reference horizon.

It accepts the initial positions 2 and 3, then scans the field in ascending order. An unhit observation position becomes a new reference. Its genealogy begins at 𝑝 +𝑝 and advances by 𝑝, marking coincidences.

During segmented execution:

  1. fill_locked_observation_segment() marks the local observation field.
  2. apply_genealogy_segment() clears genealogical endpoints using the internally generated references.
  3. Surviving marked positions form the segment's closure result.
  4. Observation endpoints and each reference's next genealogical endpoint continue into the following segment.

Stepped byte-array slice operations implement these endpoint sequences.

Internal classification uses observation-field membership and genealogical hits. Genealogy starts at 2𝑝.

Segment boundaries manage memory; they do not restart the genealogy.

4. INDEPENDENT COMPARISON

The comparison has two preparation stages:

Stage Operation
Before segment execution simple_reference_primes() independently generates the conventional base references.
After the corresponding internal segment is complete build_external_reference_segment() constructs the conventional comparison segment.

The conventional reference uses a sieve with the 𝑝2 start rule and integer alignment of multiples at segment boundaries.

The internal generator receives its own references. Conventional reference data is passed separately to the comparison functions.

The complete arrays are compared directly:

segment_exact = pbf_field == reference_field

If a mismatch occurs, the program scans the differing segment to count false positives and false negatives and locate the first deviation.

Matching counts alone do not satisfy the positional control.

5. CONTROL CONDITIONS

Condition Required result
Cumulative segment comparison Every segment matches exactly.
False positives 0.
False negatives 0.
Observation count Generated cumulative count equals the exact locked-field count.
Scale status All preceding conditions hold.
Global status Every recorded scale has PASS status.

For 𝐿 ≥5, the implemented exact observation count is:

𝑂(𝐿)=2+⌊𝐿+16⌋+max(0,⌊𝐿−16⌋).

Smaller limits are handled separately.

The first deviation is recorded as a position, or as null in JSON and NONE in the report when no deviation occurs.

6. EXECUTION REQUIREMENTS

Use Python 3 with the standard-library modules imported by the source. The supplied execution metadata records Python 3.11.9 on Windows.

No third-party packages, external datasets or network access are required. Both reference sets are generated locally.

The default segment size is 30 000 000 integer positions. Each principal byte array occupies approximately 30 MB for a full segment. Temporary slice buffers, reference lists, trace records and checkpoint data require additional memory.

The complete domain is processed in segments rather than allocated as one array.

The supplied run records approximately 84.3 minutes of segmented execution. Runtime depends on the machine and selected parameters.

Parameter Function Default

Limits are sorted and deduplicated. The engine retains limits of at least 2, and requires at least one such limit. The CLI rejects limits above 100 000 000 000.

The minimum accepted segment size is 1 000 000. Segments are shortened where necessary to end exactly at a milestone or the maximum limit.

On Windows, an interactive terminal waits for Enter before closing.

9. CHECKPOINTS AND RESTART

During continued execution, K7_CHECKPOINT.json is written after every 25 completed segments.

It records:

  • the next segment position;
  • observation and genealogical endpoints;
  • cumulative diagnostics;
  • milestone results;
  • segment trace;
  • elapsed execution time.

Checkpoint writing uses a temporary file followed by replacement to avoid exposing a partially written checkpoint.

Restart with the same output directory, milestone limits, segment size and program version. The loader checks these settings and the internal reference count before restoring state.

Execution resumes from the latest saved completed segment. Work performed after that checkpoint is repeated.

After successful final output writing, the checkpoint is removed. A later run starts a fresh execution.

A configuration mismatch raises an error rather than restoring incompatible state.

12. EXIT STATUS AND ERRORS

Exit code Meaning
0 Final output writing completes and global status is PASS.

After an interrupted or failed run, inspect the execution log, error log and checkpoint. Previously completed final files may remain until a later run replaces them.

13. LOCAL INSPECTION AND REPRODUCTION

  1. Inspect 1. Python/K7.py for observation-field construction, internal reference generation and endpoint continuation.
  2. Inspect the separate conventional reference functions and their arguments.
  3. Confirm the recorded limits, segment size and reference horizon in the JSON metadata.
  4. Trace consecutive segment boundaries and comparison results in the JSON trace.
  5. Compare cumulative milestone results across the report, data sheets and control file.
  6. For reproduction, select the intended limits and output directory, then inspect the newly generated records.

Segment numbers and inclusive boundaries identify individual comparison stages. Milestone limits identify cumulative results.

The local index and M.R.F. provide navigation and source identification. The Python source defines the operations; the output records their execution.

The local PASS covers that finite domain and the implemented positional, observation-count and mismatch controls.
