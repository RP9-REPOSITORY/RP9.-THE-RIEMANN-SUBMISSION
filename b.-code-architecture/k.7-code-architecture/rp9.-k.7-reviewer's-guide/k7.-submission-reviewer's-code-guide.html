K7. SUBMISSION REVIEWER'S CODE GUIDE

DOCUMENT OVERVIEW

This guide explains the K.7 executable, its internal positional generation, the independent external comparison, and the recorded evidence.

It distinguishes genealogical classification from external prime-reference comparison and defines the finite scope of the reported results.

1. EXECUTABLE IDENTITY

Item Identification
Code ID K7
Executable K7.py
Code title K7. P.B.F. FULL POSITIONAL GENEALOGY — 100B VALIDATOR
Version 4.1.0-100B-POSITIONAL-GENEALOGY

K.7 uses one executable Python program. No master program or additional K.7 module is required.

K.6 precedes K.7 in the relational presentation. Its recorded output is not a runtime input to the K.7 generator.

2. LOCKED OBSERVATION FIELD

The observation field consists of the initial positions (2) and (3), together with positions of the forms:

6𝑘−1and6𝑘+1,𝑘≥1,

within the declared execution domain.

K.7 constructs this field sequentially and classifies its positions through the internally generated genealogy.

Classification Internal meaning
Reproduced position An observation position reached by an earlier genealogical reference.
New closure An observation position not reached by the preceding genealogy.

New closures participate in the continued genealogy according to the implemented mechanism.

These classifications are established internally. They are not imported from external primality labels.

3. INTERNAL GENERATION

The generator uses the locked observation field and its accumulated genealogical state.

Active references advance through sequential addition. Their next left and right endpoints are retained through the next_left and next_right states.

Candidate classification does not use:

  • primality tests;
  • modulo classification;
  • divisibility queries for candidate classification;
  • factor searches;
  • a 𝑝2 start rule;
  • an externally supplied list of later positions.

K.7 therefore generates its internal classifications before comparing them with the external reference.

4. SEGMENTED EXECUTION

The domain is processed in consecutive segments to avoid allocating the complete observation field in memory.

For each segment, the executable:

  1. Constructs the local portion of the locked observation field.
  2. Carries forward the next sequential endpoints of all active genealogical references.
  3. Applies those references through sequential addition.
  4. Classifies reached observation positions as reproduced.
  5. Classifies unreached observation positions as new closures.
  6. Completes the internal segment.
  7. Constructs the corresponding independent external comparison bitmap.
  8. Compares the internal and external positional bitmaps byte for byte.
  9. Records the observation, closure and reproduction counts, false positives, false negatives and comparison status.

Segment boundaries manage memory. They do not restart the genealogy.

Each subsequent segment inherits the active references and endpoint states established by the preceding execution.

5. INDEPENDENT EXTERNAL COMPARISON

The conventional prime-base reference is generated separately before segment execution. It is not supplied to the internal genealogical generator.

For each segment, the external comparison bitmap is constructed after the internal segment has been fixed.

The comparison evaluates whether the internally generated new closures coincide positionally with the independent conventional prime reference.

Measure Meaning
Exact positional match The internal and external positional bitmaps agree byte for byte.
False positive An internal new closure has no corresponding position in the external reference.
False negative An external reference position has no corresponding internal new closure.

Agreement in total counts alone does not establish positional identity.

7. SOURCE AND EVIDENCE

The following paths are relative to K.7 CODE ARCHITECTURE.

Material Location
Executable source K.7 CODE & OUTPUT/1. Python/K7.py
Recorded output K.7 CODE & OUTPUT/2. OUTPUT/
Final report copy K.7 CODE & OUTPUT/3. FINAL REPORTS/K7_REPORT.md

The recorded output contains:

File Function
K7_CONTROL.txt Compact execution status and cumulative milestone results.
K7_DATA.json Execution metadata, segment records, scale results and summary.
K7_DATA_SHEET.csv Machine-readable milestone table.
K7_DATA_SHEET.md Human-readable milestone table.
K7_EXECUTION.log Completed execution log and status.
K7_REPORT.md Final validation report.

Without --output-dir, the executable writes to 1. Python/2. OUTPUT/ within the code package.

To write to the package-level output folder, run from K.7 CODE & OUTPUT:

python "1. Python/K7.py" --output-dir "2. OUTPUT"

The executable does not automatically copy the report into 3. FINAL REPORTS.

Two additional files may occur in the selected output directory:

File Condition
K7_CHECKPOINT.json Recovery state for interrupted execution. Removed after successful completion.
K7_ERROR.log Error details for exceptions caught by the execution handler.

These conditional files are not part of the normal completed evidence set.

The source defines the implemented mechanism. The recorded output establishes what was executed and reported.

8. TECHNICAL INSPECTION

Inspection should establish that:

  1. The executable identity and version agree with the execution metadata.
  2. Internal generation uses the locked observation field and genealogical state.
  3. External reference data does not enter internal candidate classification.
  4. Segment transitions preserve active references and sequential endpoints.
  5. External positional comparison occurs after each internal segment is fixed.
  6. The recorded statuses are supported by positional comparisons, error counts and observation-count checks.
  7. The milestone tables, execution log and final report agree.

9. RESULT SCOPE

The recorded result concerns the implemented genealogical mechanism within the executed domain through (100{,}000{,}000{,}000).

It establishes the reported finite positional agreement with the independent external reference. It does not establish agreement beyond that domain.

K.7 does not independently derive the foundational P.B.F. relations or repeat the K.6 relation, complement, scale and pulse controls. It does not perform the K.8 operator-identity, scale or Base-10 controls.

Its computational result does not independently determine the Riemann Hypothesis or constitute a formal final review.
